## 1. 结论与已确认约束

推荐建设面向家长的亲子英语练习网站：以 Markdown 管理课程，以 Vue 3 + TypeScript + Vite 构建交互界面，使用 GitHub Actions 发布纯静态产物到 GitHub Pages。学习者打开网址即可使用，不需要安装工具或登录。

已确认：

- 目标是开源到 GitHub，通过 GitHub Pages 日常使用，后续持续增加课程。
- PDF 是内容示例；大模型可以提供更准确的 Markdown。正式内容源采用 Markdown，不建设 PDF 自动导入系统。
- 进度保存在当前浏览器，支持手动导出、导入，不需要跨设备自动同步。
- 当前目录只有 `Day1-14.pdf`，没有应用、包配置、Git 仓库或可复用代码。以下代码路径均为拟新增路径，不是已有实现。

最小方案是“Markdown 转静态文章＋每日完成勾选”。推荐方案增加复习安排和周测记录，是因为它们已经存在于示例教材，且可减少家长每天手动翻找和核算复习内容的工作；不增加服务器和账号系统。

最脆弱的假设：后续 Markdown 会保持稳定结构，且经过内容校对。如果不成立，自动提取会错位、课程质量会下降。通过显式模板、构建校验和逐课审核解决，格式不合格时阻止发布，不尝试猜测修复。

## 2. PDF 告诉我们的产品需求

来源：仓库根目录 `Day1-14.pdf`，共 8 页；已提取全部页面文字，并对第 2、8 页进行渲染核对。

教材定位是家长具有 CET-4 基础、孩子处于听力启蒙期，每日约 10–15 分钟。核心交互是家长说英语、配合手势，孩子听懂后做动作，不要求孩子英文回答。

| 课程 | 场景 | PDF 页码 |
| --- | --- | --- |
| Day 1 / 8 | 晨间唤醒、穿衣洗漱 | 2 / 5 |
| Day 2 / 9 | 早餐、出门 | 2 / 5–6 |
| Day 3 / 10 | 接娃、回家洗漱 | 2–3 / 6 |
| Day 4 / 11 | 用餐、餐桌礼仪 | 3 / 6–7 |
| Day 5 / 12 | 收纳、家务 | 3–4 / 7 |
| Day 6 / 13 | 户外、超市、出行 | 4 / 7–8 |
| Day 7 / 14 | 周测、睡前指令 | 4–5 / 8 |

内容规模：12 个普通学习日，每日 4 条主指令，共 48 条；2 个周测日，每日 2 条睡前指令，共 4 条；两次周测分别包含 3 个孩子动作任务和 3 个家长表达任务，总计 12 个测评任务。主指令合计 52 条，不包含替换句和复习组合句。

普通指令包含英文、中文、连读/重音/易错音提示、动作引导和替换表达；周测区分孩子听懂照做与家长看中文说英文，不能设计成统一选择题。

示例存在的结构问题及处理：

- 第 1 页说每页精确安排两天，实际多处跨页。网站按课程组织，不继承分页布局。
- 第 1 页 Day 8 动词摘要包含 `turn...right side out`，正文使用 `Your shirt is inside out. Let's fix it.`；摘要不能作为正文的事实来源。
- Day 9 复习标题含 Day 7，但对应第二段没有明确覆盖其睡前指令；Day 10、11、13 也有标题引用与正文覆盖不一致的情况。复习由已学习课程和日期计算，原文组合句只作附加练习。
- 类似 `Pu-don` 的拼读提示是原稿辅助记法，不能当成标准音标；Markdown 格式准确不等于语言知识准确。内容审核须分别检查英文、中文、音标和动作引导。
- 保留原稿“1/2/4/7 天”作为产品复习规则，界面称“间隔复习”，不承诺这是对所有人的最佳学习曲线。

PDF 不作为最终课程数据库，也不要求后续每批内容附带 PDF。首批 Markdown 可由大模型依据示例重新整理，必须保留课程覆盖并记录修订。

## 3. 首版范围与成功标准

首版一次交付完整可用网站，包括课程浏览、每日学习、间隔复习、周测、浏览器进度、备份恢复、Markdown 增量发布和 Pages 部署。

成功标准：

1. 手机浏览器能在一屏内找到“继续学习”和“到期复习”，课程英文和动作引导容易阅读。
2. 首批覆盖 Day 1–14 的全部主题、52 条主指令和 12 个周测任务；最终表述以审核后的 Markdown 为准。
3. 中途退出、刷新和下次打开能恢复学习位置、任务记录与完成状态。
4. 新增符合模板的 Day 15 Markdown，无需修改 Vue 页面、路由或手写课程索引即可构建发布。
5. 同一进度文件在另一浏览器导入后，课程完成状态、复习阶段、周测结果一致。
6. Pages 项目子路径下资源、深链接和刷新正常，失败的校验不会覆盖线上版本。

首版不做：在线大模型调用、自动生成课程、PDF/OCR 导入、登录、多孩子档案、云同步、语音识别或发音评分、排行榜、推送通知、后台 CMS、离线 PWA、自定义域名。无埋点、遥测、第三方字体/CDN 或额外业务网络服务。

## 4. 页面与学习流程

| 页面 | 路由 | 主要内容 |
| --- | --- | --- |
| 今日 | `#/` | 继续学习、到期复习、已完成课程数；无到期任务时显示明确空状态 |
| 课程 | `#/lessons` | 按顺序列出全部课程，按主题筛选、按中英文搜索 |
| 学习详情 | `#/lessons/:id` | 学习目标、指令卡、原稿复习情境、周测、完成按钮 |
| 复习 | `#/review` | 按到期时间排列已学课程，逐课打开指令卡并标记本次完成 |
| 进度与备份 | `#/progress` | 学习历史、周测结果、JSON 导出导入、清空本地记录 |

首次访问直接显示 Day 1，无设置向导；之后优先回到上次未完成课程，其次推荐序号最小的未完成课程。允许自由浏览和提前学习，不强制按星期解锁。Day 表示课程顺序，不能与真实星期绑定。

普通学习日建议：复习 3–4 分钟，新指令与动作实践 6–8 分钟，简短回顾 1–3 分钟。时间仅作为建议，不用倒计时强制结束。

每张指令卡默认显示英文、中文和动作引导；发音提示、替换句可展开。记录“独立完成 / 提示后完成 / 再练一次”，默认未记录。家长主动点击“完成本课”才算完成，记录未齐时列出遗漏并提供“继续练习”或“仍然完成”，不把浏览、朗读次数当成掌握。

周测日使用两个独立区块：孩子任务显示家长应说的英文，家长记录动作表现；家长任务先显示中文情境，点击后揭示参考英文，自评“说出 / 需提示 / 再练”。不自动判断同义句错误，不要求孩子看屏幕操作。

视觉方向：移动优先、浅暖底色、深色正文、单列指令卡；桌面可采用课程目录＋内容双栏。英文与中文有清晰层级，重音用粗体，连读保留 `‿`。所有按钮可键盘操作，状态同时有文字，不只靠颜色；320px、375px、768px 和桌面宽度无横向溢出。

### 可选能力：设备本地朗读

首版提供能力检测后的单句播放，使用浏览器 SpeechSynthesis，只选择 `localService=true` 的英语语音，优先 en-US，其次其他英语本地语音。不使用远程语音，不要求安装语音包。

用户点击才播放；支持停止，播放下一句时取消上一句，离开页面时停止。朗读文本移除显示用连读符号和 Markdown 标记。无可用本地语音或播放失败时显示“当前设备暂无本地英语朗读，请由家长示范”，保留完整文本流程。此功能是辅助示范，不保证所有设备声音一致或等同真人示范。

## 5. 复习和进度规则

采用“首次完成课程日期＋1、2、4、7 个自然日”的固定节点，使用用户浏览器当地日期，按日历日期计算，不使用毫秒除以 24 小时。首版不做自适应记忆算法。

- 首次完成才设置 learnedOn；再次打开、再次完成不会重置它。
- 到期任务只来自已完成课程；未学课程不加入复习。
- 每课同一天最多出现一次。漏学多天导致多个节点过期时，合并为一次复习，展示覆盖的到期节点；完成后只关闭这些已到期节点，未来节点不变。
- 过期任务保留，不把所有任务挤成强制当天完成；列表按最早到期、课程序号排序，家长可停止后续继续。
- 同一天重复点击完成不重复推进节点；“再练一次”保留任务，不记为已复习。
- 课程的全部主指令均可在复习页展开；PDF 的串联情境作为辅助，不决定实际覆盖。
- 全部 14 天学完仍能进行剩余复习；没有 Day 15 时显示“本批课程已完成”，不访问不存在的课程。

示例：Day 1 在 11 月 4 日完成，则 11 月 5、6、8、11 日到期。11 月 8 日才回来时，该课只显示一条任务，完成后覆盖第 1/2/4 天节点，第 7 天节点仍在 11 月 11 日。

进度存储使用命名空间 `dailyenglish:parent-child-english:v1`。保存 schemaVersion、courseId、最近访问课程、每课首次学习日期和完成时间、逐条指令状态、周测状态、已完成复习节点及时间。稳定 lessonId/itemId 是关联键，不能用数组位置。

课程文案修改增加 revision，保留旧进度并提示“内容已更新，可再练”；已经发布的 ID 永不复用。暂时删除的课程记录作为孤立记录保留并随备份导出，不显示在当前学习列表中。

存储失败时保留内存状态并提示“本次进度未保存，请导出备份”；读取损坏数据时不自动覆盖原数据，允许导出原始备份后重置。页面显示进度仅保存在本浏览器，清除站点数据会丢失记录。

备份文件为 JSON，含 format=`dailyenglish-progress`、schemaVersion=1、courseId、exportedAt 和完整进度。导入限制 5 MB，先校验格式、版本、字段类型、日期及状态枚举，拒绝未知高版本；失败不改现有记录。合法但课程尚不存在的 ID 保留。导入采用整份替换，不做隐式合并；展示摘要并让用户确认，提供导出当前备份入口；写入成功后才替换界面状态。

## 6. Markdown 内容契约

以 `content/lessons/day-001.md` 至 `day-014.md` 作为首批正式源文件；后续按序增加。一个文件就是一课，程序从文件自动生成索引。`content/README.md` 记录编写规则，`content/templates/daily.md` 和 `assessment.md` 提供两种可复制模板。模板说明不参与课程扫描。

### 元数据

使用 YAML front matter，字段约定如下；这是拟新增接口，不是现有配置。

| 字段 | 类型与规则 |
| --- | --- |
| schemaVersion | 整数，首版固定 1 |
| courseId | 字符串，固定 parent-child-english |
| id | 唯一稳定字符串，首批 day-001 至 day-014 |
| order | 唯一正整数，决定课程顺序，不限制最大天数 |
| title | 非空中文标题 |
| kind | daily 或 assessment |
| theme | morning、breakfast、homecoming、mealtime、chores、outdoors、bedtime 之一 |
| estimatedMinutes | 正整数，首批 10–15 |
| revision | 正整数，内容修订时递增 |
| reviewStatus | draft 或 reviewed；正式构建拒绝 draft |
| source | 来源说明，首批注明依据 Day1-14.pdf 整理及对应页码；新内容注明大模型辅助生成 |

### 正文结构

- 二级标题固定为“学习目标”“热身与复习”“今日指令”；assessment 另含“孩子动作测评”“家长表达自测”。
- “热身与复习”是普通说明文字，可以引用其他课的稳定 ID；不承担日程计算。仅允许引用存在且序号更早的课程。
- 每条指令用三级标题标识稳定 ID，例如 day-001-i01；四级标题固定为“英文”“中文”“发音提示”“动作引导”“替换表达”。
- 英文允许粗体表示重音、`‿` 表示连读。发音提示为普通文字；音标沿用标准字符。替换表达为列表，每项按“英文｜中文”写完整配对。
- 普通课允许 1–8 条指令，周测课允许 0–8 条；首批普通课必须 4 条、周测课必须 2 条，以单独首批覆盖测试保证，不将此数量限制写死到通用渲染器。
- 孩子测评条目用稳定 ID，固定包含“情境”“英文”“观察要点”；家长自测固定包含“中文情境”“参考英文”。每组允许 1–10 项，首批各 3 项。
- 禁止原始 HTML、脚本、嵌入 iframe、外链图片和远程资源。首版不支持课程内图片，避免引入资源管线。

使用 unified/remark-parse 解析 Markdown AST、yaml 解析头部，按固定标题映射为类型化课程数据；不靠正则切割整篇文档，不把任意 Markdown 转成未经处理的 HTML。只支持段落、列表、粗体、强调与文本；不支持的节点在校验时报告文件和位置。

自动检查负责语法和结构，包括重复 ID/order、缺段落、空文本、错误枚举、失效引用、非法节点；不能证明英文地道或音标正确。reviewed 由维护者完成内容检查后设置，大模型不得自行声明审核通过。

## 7. 持续增加内容的工作流

1. 维护者将模板、已有主题清单和目标 Day 范围交给大模型，要求输出独立 Markdown 文件，不附带解释性聊天文本。
2. 新文件放入 `content/lessons/`，默认 draft。为避免改坏已有记录，不重排或重用已发布 ID。
3. 执行 `npm run content:check` 检查所有源文件，允许 draft 但列出审核状态。
4. 对照示例检查英文、翻译、发音说明和儿童动作适配性；确认后改为 reviewed。修订旧课同步增加 revision，并在内容变更记录写明原因。
5. 本地预览，再提交 PR；CI 检查正式内容全部 reviewed，执行测试与构建。
6. 合并 main 后自动发布。新课程自动出现在课程列表，不修改页面代码，也不手工编辑编译后的 JSON。

首批优先使用重新整理的 Markdown，不做机械 PDF 转换；逐课核对主题、数量和周测覆盖。没有英文校对依据的发音断言不标记为已审核事实。

## 8. 技术方案与复杂度控制

推荐 Vue 3 Composition API、TypeScript、Vite、Vue Router hash 模式、原生 CSS；不引入 UI 组件库、全局状态框架、数据库和运行时服务器。Vitest 测试内容解析与业务规则，Playwright 验证完整浏览器流程。

这是空目录新项目，预计新增超过 8 个文件，包括 14 个课程文件、应用、测试、文档和部署工作流；没有新增后端服务。统一采用 Node.js 工具链，PDF 阅读使用的 Python 不进入项目依赖。

```text
Markdown 课程 -> 构建校验/转换 -> 静态课程索引与分课 JSON
                                      |
                                      v
                               Vue 学习/复习/周测页面
                                      |
                                      v
                              进度与复习规则模块
                                      |
                                      v
                              localStorage <-> JSON 备份

main -> Actions 检查/构建 -> Pages 静态文件 -> 浏览器
```

构建过程单向，页面不回写 Markdown；本地进度不上传。首页只读轻量索引，课程详情按课加载，避免未来 140 天内容全打入首屏包。加载失败显示重试按钮，不自动循环请求。

拟新增文件职责：

| 文件/目录 | 职责 |
| --- | --- |
| package.json、package-lock.json、tsconfig.json、vite.config.ts | 依赖锁定、类型检查、构建 |
| content/lessons/、content/templates/、content/README.md | 课程源、模板与编写规范 |
| scripts/content.ts、src/domain/content.ts | 校验、AST 转换及课程类型 |
| src/main.ts、src/App.vue、src/router.ts | 应用入口与路由 |
| src/views/TodayView.vue、LessonsView.vue、LessonView.vue、ReviewView.vue、ProgressView.vue | 五个页面 |
| src/components/InstructionCard.vue、AssessmentPanel.vue | 可复用指令和测评界面 |
| src/domain/progress.ts、review.ts、backup.ts | 持久化契约、复习计算、导入校验 |
| src/composables/useProgress.ts、useSpeech.ts | 页面状态与本地语音能力 |
| src/styles/main.css | 响应式与可访问性样式 |
| tests/、e2e/ | 单元、内容完整性、浏览器测试 |
| .github/workflows/ci.yml、deploy.yml | PR 检查与 main 发布 |
| README.md、LICENSE、CONTRIBUTING.md、docs/内容修订记录.md | 开源说明、许可、贡献和修订记录 |

新增开发命令统一为 `dev`、`content:check`、`typecheck`、`test`、`test:e2e`、`build`、`preview`。build 先进行严格内容校验并生成静态数据再构建，dev 自动监听 Markdown 变化；生成目录不人工编辑、不提交。没有应用环境变量、业务 API、密钥或可调复习算法开关。

Vite 项目路径在 CI 根据 GitHub 仓库名计算：普通仓库使用对应子路径，账号主页仓库使用根路径；所有资源用构建 base 生成。Hash 路由避免对 Pages 服务器增加 SPA rewrite 要求。

不选文档站生成器作为首选：若仅阅读 Markdown，它更简单；但本项目主要价值是本地进度、复习安排和两种测评，仍需编写较多交互。若需求缩减为纯阅读，可改为文档站。服务器＋数据库方案没有被当前同步需求支持，成本明显更高，不采用。

## 9. 验证与验收

## 10. GitHub 开源、部署与回滚

推荐公开仓库名 DailyEnglish、默认分支 main。代码采用 MIT；原创课程与文档建议 CC BY 4.0，并在 README 中区分许可范围。原 PDF 暂不纳入首版公开发布产物；正式课程来源和修订需可追溯。具体账号归属及内容许可由用户在实际发布前确认，不影响本地实现。

所需账户与凭证：只有用于创建/管理仓库的 GitHub 账号，以及本机 Git 的既有认证。CI 使用 GitHub 自动提供的 GITHUB_TOKEN 和 Pages OIDC，构建读仓库，部署授予 pages:write、id-token:write；无需人工创建应用 API key，也不把凭证放进前端或课程文件。

发布顺序：

1. 在已确认账号下创建公开 DailyEnglish 仓库，提交审核后的代码、Markdown、许可证和使用文档，排除进度备份、临时 PDF 渲染、node_modules、dist。
2. PR 运行内容检查、类型检查、单元测试、构建和浏览器测试；来自 PR 的代码只检查，不部署。
3. 仓库 Settings → Pages 的 Source 选择 GitHub Actions，使用官方 Pages artifact/deploy 流程。
4. main 更新触发检查、构建、上传 dist、部署；同一 Pages 部署组串行，失败不发布新产物。支持手动 workflow_dispatch 重部署。
5. 记录 Actions 返回的真实站点地址，在 README 和仓库 About 填入；完成上一节线上验收。

不预先虚构 GitHub 用户名、远程地址或部署成功状态。实施者在发布步骤读取当前账号与仓库状态；若无授权登录，由用户完成 GitHub 登录后继续，不能让用户把 token 贴进聊天。

回滚应用或课程：对有问题提交做 revert，再部署已验证版本，不强推历史；浏览器数据保持原样。schemaVersion=1 首版不做破坏性迁移。误导入备份通过此前导出的文件恢复，整份替换前必须明确提示。需要停止公开访问时在 Pages 设置取消发布，仓库和本地进度仍保留。

依赖失败：Actions/npm 不可用时不更新线上版本；Pages 不可达时无法保证新打开页面可用，首版不以离线缓存掩盖这一限制。朗读不可用回到家长示范，不阻断课程。10 倍内容规模主要增加构建校验量，分课静态文件避免首屏包线性膨胀；10 倍访问量不增加应用服务器负担。

## 11. 实施交接与前置条件

建议作为一个可发布首版交付，不把不可独立使用的框架搭建标成独立产品阶段。工程内部依次完成内容模板与首批整理、学习与复习闭环、数据备份、测试、公开发布。后续每批 Markdown 更新均可独立上线，不依赖新增功能。

估计投入：单人约 4–6 个工作日，含首批整理、交互、规则测试与 Pages 验收；英文及发音逐条审核可能额外占用 1–2 天。这是范围估计，不是交付承诺。

本轮已核实：Node.js v24.15.0、npm 11.8.0、Git 2.36.1 可运行；PDF 全文可读取；GitHub Pages、Vite、Vue Router、MDN 官方说明可以访问。npm 读取用户配置会输出若干旧配置项警告，本轮未修改用户配置。

未核实且有明确负责人：

- GitHub 账号、仓库创建权限、Pages 配置权限：用户提供目标账号，实施者在发布前读取验证；本轮未发现 gh 命令，不把 gh 作为必要条件。
- npm 依赖安装与 Playwright 浏览器：实施者在获准实现后安装并验证；本轮没有安装依赖。
- 手机本地英语语音可用性：实施者与用户在设备验收时确认；能力缺失已有文本降级，不阻塞方案。
- 首批 Markdown 的语言质量与内容许可：维护者在标记 reviewed 和公开发布前确认；自动化只验证结构，不能替代这一步。

方案确认点只有方向与范围：采用 Markdown 为源、纯静态部署、家长主导 TPR、按实际学习日期复习、本地进度与手动备份。用户已经确认最后一项。确认方案后可开始本地实施；公开发布时使用实际账号及完成的可审查产物。
